# 作業指示書テンプレート

`docs/codex-work-orders/YYYY-MM-DD-<slug>.md` にこの構成で作成する。見出しは固定、中身はタスクに合わせる。「完了報告」節は空欄のまま置き、Codex に埋めさせる。

```markdown
# 作業指示書: <タスクの短い要約>

- status: 依頼中
- 作成日: YYYY-MM-DD
- 依頼元: Claude Code セッション

## 背景と目的

<なぜこの変更が必要か。Codex はこの文書以外の文脈を持たないので、
会話で共有済みの前提もここに書き直す。>

## 実装方針

<Claude が決めた設計。触るファイルと役割、変更の流れ、
従うべき既存パターン（具体的なファイル・関数名で示す）。>

### 変更対象ファイル

- `path/to/file1` — <何をするか>
- `path/to/file2` — <何をするか>

## 制約

- `AGENTS.md` の Safety Rules に従うこと。
- <タスク固有の制約。例: 既存の公開 API のシグネチャを変えない、
  ○○ のスタイルに合わせる、など>

- <触ってはいけないファイル、やってほしくないリファクタリング。
  「気づいた別の問題は直さず完了報告に書く」を必ず入れる>
- 気づいた別の問題は直さず、完了報告の「残課題・気づき」に書く。

3. ...
```

## status の遷移

- `依頼中` — Claude が作成し、Codex に渡した状態
- `差し戻し` — 検収で設計レベルの問題が見つかり、「差し戻し」節を追記して再依頼した状態
- `完了` — 検収を通過した状態

差し戻すときは文書末尾に `## 差し戻し (N回目)` 節を追記し、何が・なぜ受け入れ基準を満たさないか・どう直すかを書く。
