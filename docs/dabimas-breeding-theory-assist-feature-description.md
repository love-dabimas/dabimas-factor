# ダビマス「配合理論補助」機能説明・既存ライブラリ解析整理

- 文書状態: ダビふぁく仕様化前レビュー用
- 改訂日: 2026-09-12
- 目的: 同プロジェクト内で実施済みのゲームライブラリ解析と画面確認を基に、配合理論補助の機能を説明する
- 確信度: 高（画面挙動と解析済みロジック）／中（画面固有の内部接続名）

## 1. 結論

ダビマスの「配合理論補助」は、繁殖牝馬を起点として各世代の種牡馬を手動で選び、選択した配合で生まれる仮想産駒の血統を次代へ引き継ぎながら、最大3代先までの成立理論・系統構成・有効なインブリード因子を確認する配合計画機能である。

画面は前工程に依存する。1代目の種牡馬が未選択なら後続世代は操作できない。種牡馬を選択すると、その配合で生まれる産駒を次代の繁殖牝馬として血統を組み直し、後続世代の候補と判定結果を再計算する。

この機能の本質は、完成済みの父母2頭を1回判定することではない。工程ごとに「父となる種牡馬」と「前工程から生成された母」を組み合わせ、産駒血統を次工程へ順次渡すことで、将来の配合経路を試行できる点にある。

## 2. 利用者向け機能説明文

### 2.1 標準版

「配合理論補助」は、繁殖牝馬を起点に、これから行いたい配合を3代先まで試せる機能です。

各世代で種牡馬を選ぶと、その組み合わせで生まれる産駒の血統が自動的に組み立てられ、成立する配合理論や有効なインブリード因子が表示されます。作られた産駒は次代の繁殖牝馬として扱われるため、種牡馬を順番に選びながら、2代目、3代目へと配合を積み上げられます。

前の世代で種牡馬を変更した場合は、その産駒の血統が変わるため、後ろの世代も新しい血統を基に再計算されます。実際に種付けや生産を行う前に、手持ちの種付け権で狙った配合理論が成立するか、途中の配合を含めて確認するための機能です。

### 2.2 短縮版

繁殖牝馬に種牡馬を代ごとに重ね、仮想産駒の血統を次代へ引き継ぎながら、3代先までの配合理論と有効因子を確認する機能です。

## 3. 画面確認から判明している操作構造

以前の画面確認では、次の状態が確認されている。

| 画面状態 | 確認内容 |
| --- | --- |
| 1代目未選択 | 後続世代は使用できず、前工程の選択を要求する |
| 種牡馬候補表示 | 選択可能な種牡馬と、その組み合わせで成立する理論が一覧表示される |
| 種牡馬選択後 | 産駒の系統、配合理論、有効なインブリード因子が再計算される |
| 次代へ進む | 直前の配合で生成された産駒を繁殖牝馬側として、次の種牡馬を選択する |

基本フローは次のとおり。

1. 起点となる繁殖牝馬を選択する。
2. 1代目の種牡馬候補を開く。
3. 候補ごとに表示される成立理論を確認して、種牡馬を選択する。
4. 選択した父母から1代目産駒の血統・系統を生成する。
5. 1代目産駒を次代の繁殖牝馬として扱う。
6. 2代目の種牡馬を選び、理論と有効因子を再計算する。
7. 同じ処理を3代先まで繰り返す。
8. 前工程を変更した場合は、その工程以降の仮想血統と判定結果を組み直す。

## 5. 配合理論表示の解析結果

### 5.1 成立判定と画面表示は別である

内部では複数の理論が成立し得るが、画面には `priority` の高い理論を代表として1件表示する。

確認済みの表示優先順位は次のとおり。

```text
危険な配合
  > 至高の配合
  > 奇跡の配合
  > 超完璧な配合
  > 完璧な配合
  > 見事な配合
  > よくできた配合
  > 面白い配合
```

`DANGEROUS` は優先度999で最優先となる。したがって、面白い配合などと危険な配合が同時に成立した場合でも、ゲーム画面の代表表示は「危険な配合」になる。

ダビふぁくでは、次の2値を分けて保持する必要がある。

| 値 | 用途 |
| --- | --- |
| `matchedTheories` | 内部で成立した理論の一覧 |
| `displayedTheory` | 優先順位により画面へ表示する代表理論 |

### 5.2 `dispTheory()` が参照する親系統位置

解析済みの `dispTheory()` では、種牡馬側・繁殖牝馬側の所定位置から親系統を取り出して理論判定へ使用する。

```text
S[1] = parentLines[9, 11, 13, 15]
S[0] = parentLines[1, 3, 5, 7]
D[0] = parentLines[17, 19, 21, 23]
```

ダビふぁくへ移植するときは、画面セル番号を直接判定ロジックへ渡すのではなく、意味を持つ血統パスへ変換してから使用する。

### 5.3 通常理論の整理

| 理論 | 判定の骨格 |
| --- | --- |
| 面白い配合 | 父母双方の指定4系統、計8枠の親系統種類数で判定 |
| 見事な配合 | 種牡馬側の見事系統4枠と繁殖牝馬側4枠の構成一致 |
| 完璧な配合 | 見事な配合と面白い配合を同時に満たす |
| 超完璧な配合 | 見事条件を満たし、対象8枠の親系統が8種類 |
| 奇跡の配合 | 完璧条件に加え、指定位置で4×3の一致がちょうど1つ成立 |
| 至高の配合 | 同一馬3クロスと因子種類数など、専用条件で判定 |
| 危険な配合 | インブリードの重なりなどを専用判定し、表示時は最優先 |

## 6. インブリードと因子表示の解析結果

- `getCrossCommentType()` は、配合理論の代表表示を決める関数ではなく、インブリードのクロスコメント種別を決める別経路である。
- `getCrossFactorCount()` 系の処理では、画面表示行を持たないクロス群もカウント対象に含める必要がある。
- 同一馬判定、全兄妹判定、自家製馬とマスタ馬の混在は、表示名だけではなく永続IDと親構成を使って扱う。
- 種牡馬の称号・年号などvariant単位の因子参照と、実馬としての同一性判定は分離する。

配合理論補助では、各工程で新しい仮想産駒血統を作るため、理論表示だけでなく、同一祖先の出現位置と有効因子も工程ごとに再計算する必要がある。

## 7. ニックス計算の解析結果

配合理論補助に相性情報を含める場合、解析済みの `PedigreeTree::getNicksPoint` を使用できる。

### 7.1 関連関数

| 名称 |
| --- |
| `CollectionMasterNick::getNickPoint` |
| `getNicksCommentID` |
| `PedigreeTree::getNicksPoint` |
| `isMiracleBloodVolumeForNicks` |
| `getSireLineIDsForNicks` |

### 7.2 繁殖牝馬側の参照4系統

| slot | 血統パス |
| ---: | --- |
| 0 | 父 |
| 1 | 母父 |
| 2 | 母母父 |
| 3 | 母母母父 |

種牡馬自身の `sire_line_id` と、上記4系統との有向ペアを `nicks` マスタから参照する。

### 7.3 計算上の重要事項

- 種牡馬レアリティ1〜5ごとに4枠のウェイトが異なる。
- 同じ繁殖牝馬側系統が再登場した場合、2回目以降の相性点は1.0に置き換える。
- 各枠をウェイト乗算後に個別に切り上げ、それから合計する。
- 奇跡の血量条件が成立し、slot0の項が6以上なら合計へ3点を加算する。
- `nicks` の検索は有向であり、逆向きの組み合わせを自動検索しない。

相性関連5テーブルは、スキーマと件数の合計352レコードが確認されている。ただし、当時の初期ライブ抽出で具体的な平文値まで確認できたのは `nicks/1` の1件であり、352件すべての値を取得済みという意味ではない。

## 9. 機能として扱う範囲

### 9.1 ゲーム側で確認できた基本機能

- 起点繁殖牝馬の選択
- 各世代の種牡馬選択
- 前工程の産駒血統を次工程へ継承
- 3代先までの配合計画
- 候補種牡馬ごとの成立理論表示
- 選択後の血統・系統・理論の再計算
- 有効なインブリード因子の表示
- 前工程未選択時の後続工程無効化

### 9.2 ゲーム機能と混同してはいけないダビふぁく独自案

- 4代配合計画
- 血統表の全枠入力後に押す一括診断ボタン
- 途中工程の危険件数集計
- 危険工程の種牡馬セルへの `⚠` 表示
- 判定不能工程の件数・理由表示
- `snapshotHash` による診断結果整合性確認

これらは既存の「配合補助・工程危険診断」仕様で設計した拡張であり、ゲームの配合理論補助そのものの解析結果ではない。

## 10. ダビふぁくへ落とし込む際の中核要件

1. 起点の既存・自家製繁殖牝馬を選択できる。
2. 各工程で既存・自家製種牡馬を手動選択できる。
3. 前工程が確定するまで後続工程を操作できない。
4. 選択した種牡馬と現在の母から、次代用の仮想繁殖牝馬血統を生成する。
5. 仮想繁殖牝馬は血統マスターへ恒久登録せず、配合計画内の派生データとして保持する。
6. 各工程で血統、親系統、成立理論、代表表示理論、インブリード、有効因子を再計算する。
7. 前工程を変更したら、その工程より後ろの仮想血統と結果をすべて無効化して再構築する。
8. `matchedTheories` と `displayedTheory` を分離する。
9. 種牡馬variantの因子は `node_id`、実馬同一性は `pedigree_id` を基準に扱う。
10. まずゲーム準拠の3代先までを基本機能とし、4代目や工程危険診断は独自拡張として分離する。

## 11. 現時点で未確定の接続事項

以前の解析では判定ロジックと画面挙動は確認できているが、配合理論補助画面に限定した次の内部名は記録として確定していない。

- 画面コントローラまたはLuaモジュールの正式名
- 種牡馬候補一覧を生成する画面固有関数名
- 画面内の仮想繁殖牝馬を生成する関数名
- 3世代分の選択状態を保持するフィールド名
- 画面を閉じた後の計画保存・復元形式

これらはダビふぁくの機能説明を作るうえでは必須ではないが、ゲームと同一の内部構成を再現する仕様書を書く場合は追加確認が必要になる。

## 12. 仕様書化するときの機能分割

| 機能 | 責務 |
| --- | --- |
| 起点牝馬選択 | 配合計画の第1工程へ母データを渡す |
| 種牡馬候補表示 | 現在の母に対する候補と代表理論を表示する |
| 工程確定 | 選択した父母の組み合わせを工程へ保存する |
| 仮想産駒生成 | 父母を接続した次代用血統を生成する |
| 理論判定 | 全成立理論と代表表示理論を返す |
| クロス・因子判定 | 同一祖先、クロス位置、有効因子を返す |
| 後続無効化 | 上流変更時に下流工程を削除・再計算する |
| 計画表示 | 3代分の選択状態と結果を表示する |
| 独自危険診断 | 全工程をまとめて検査し、途中危険を通知する |
