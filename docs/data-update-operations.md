# データ更新の運用

| 実行 | 起動 → 公開基準（JST） | データ源 |
|---|---|---|
| 毎日 | 09:47 → 11:30 | 公開済み JSON ＋ R2。全書にはアクセスせず、新馬の追加と全馬の血統更新 |
| 金曜 | 13:07 → 18:30 | 全書を全件取得し、R2 で血統を更新。日次追加馬の ID を引き継ぐ |

GitHub schedule の遅延に備えて前倒し起動し、予定時刻まで待機する。
`as_of` は当日の予定時刻に固定され、遅れて起動しても変わらない。
`display_start_at <= as_of` の馬を追加するため、12:00 開始の馬はその日の日次には入らず、翌日の日次で出る（金曜の完全更新が先に拾う場合もある）。
種牡馬の開始日時 0 / null、牝馬の開始日時のキーなしは制限なし。

日次で追加できるのは **R2 に載っている馬だけ**。マスターは採取パイプラインを手動で回さない限り更新されない。
R2 に無い馬は金曜の全書から拾うが、血統を解決できない場合は更新全体を止める。
牝馬の日次追加は schema v6 以上の検証済み開始日時が必要。v5 または未指定なら追加せず警告して続行する。
状態は Actions のログと `audit.json` の `mares_disabled_reason` で確認する。

新しい種牡馬の ID は `sg{ゲームID}`、牝馬は `bg{ゲームID}`。
金曜に全書が追いついてもこの ID は維持する。未掲載の馬も開始済み・active なら持ち越す。
全行の `gameId` はダビ娘との照合用のゲーム本体番号で、full と summary の `nodeId` の直前に出る。マスターと対応しない場合は null。
`scripts/data/game_exclusions.json` は追加・持ち越しを除外するゲーム ID 一覧。変更時は `reasons` に理由を書く。日次では既存馬を削除しない。

生成先は `build_out/`。整合性検証を通してから4種の公開成果物を比較する。
`pedigreeNodes.json` の `datasetVersion` だけの差は更新としない。
変更なしなら commit・X 投稿はせず、Actions の Summary に「変更なし」と出る。
変更ありなら画像を作り、公開データと CACHE_NAME を同じコミットで反映し、push 成功後に X へ投稿する。同日の CACHE_NAME は連番を進める。

処理失敗時は公開データを維持する。依存導入済み・push 未成功・dry_run でない場合にエラー通知するが、直前の完了 run も failure なら連投しない。
履歴の取得失敗時は通知する。push 後の X 投稿失敗は Actions に失敗として残し、更新失敗の通知は出さない。
R2 の版の不一致は60秒待って2回まで再取得する。CI にはキャッシュを復元しないため、取得失敗時のキャッシュ代替はない。

手動の予行（公開・投稿なし。成果物と監査 JSON は artifact で確認）:

```bash
gh workflow run x_post.yml --ref <枝> -f mode=daily -f dry_run=true -f as_of=2026-10-13T11:30:00+09:00
```

全書を取り直す予行は `-f mode=weekly`。実際に公開する場合は `dry_run=false` とし、未来の `as_of` は指定しない。`as_of` が空なら現在時刻を使う。
