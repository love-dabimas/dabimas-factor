# ダビ娘統合（検索・お気に入り・単体画面）詳細設計書 v1.5

改訂履歴: v1.0 初版（2026-09-11）。調査結果と、iPhone で 7 ラウンド触って決めたプロトタイプの結論をまとめた。→ v1.1 未決事項のうち 3 件（旧ダビ娘の扱い、「お気に入りのみ」の共通化、同名で ❤ あり・なしが並ぶ件）をユーザー確認のうえ確定（2026-09-11、§10）。→ v1.2 アプリ名を当面「ダビふぁく」のまま据え置くと確定（2026-09-11、§10.2）。→ v1.3 移行案内のバナーを Phase A から外し、Phase C として着手を保留（2026-09-11、ユーザー指示、§8・§9）。→ v1.4 §9 の「フェーズ 2f が進行中」は誤りだったので訂正（2f は 2026-09-10 に検収済み）。→ v1.5 Phase B を実装・検収（2026-09-11、`8713e89` と検収時の修正）。作業指示書 `docs/codex-work-orders/2026-09-11-musume-integration-phase-b.md` で決めた点を §4・§5・§6・§7.1・§11.1 に反映し、§9・§12 に実装と確認の状況を足した。

## 0. このドキュメントの位置づけ

ダビ娘（`love-dabimas/dabimas-data`、React）をダビふぁく（`love-dabimas/dabimas-factor`、Vue 2）の中に取り込み、1 つのホーム画面アプリ（PWA）にするための詳細設計である。**ダビ娘はダビふぁくの中に同一オリジンの iframe として埋め込み、お気に入りの正本はダビふぁくの IndexedDB に置く。** 画面の見た目と操作は、`tmp/prototype-search-modal/` のプロトタイプを iPhone で触って決めた（経緯は付録 A）。

対象ブランチは `feature/dabifaku-unified`。`docs/dabifaku_unified_spec_draft.md`（統合版実装仕様書、以下「統合版仕様」）のカテゴリ・作業枠・ホーム画面が実装済みであることを前提とする。本書のコード参照は 2026-09-11 時点のもので、行番号がずれていたらメソッド名で探すこと。

### 0.1 実装時の原則

- 確定事項は本書に従う。現行実装と本書が食い違ったら、勝手に解釈せず報告する。
- ダビふぁく側の新規ファイルは IIFE ＋ `window.Dabimas` 名前空間、classic script、UTF-8 BOM なし。Vue 2 / Vuetify 2 を維持し、新しいライブラリは足さない。
- 新規ファイルは `index.html` の script タグと `service-worker.js` の `urlsToCache` の両方へ追加し、`CACHE_NAME` を上げる。
- `index.html` を編集するときは `AGENTS.md` の手順（バックアップ → apply_patch → verify-index-exp）に従う。
- ダビ娘側は別リポジトリ（`dabimas-data`）の作業になる。埋め込みのときだけ見た目と挙動が変わるようにし、単体で開いたときの見た目は今と同じに保つ。

### 0.2 要件（ユーザーの指示の要約）

1. ダビ娘とダビふぁくを統合し、ホーム画面のアイコンを 1 つにする。
2. ダビ娘で ❤ を付けた馬だけを、ダビふぁくの馬の選択肢に出せるようにする。
3. ダビ娘には利用者が案外いるので、ダビふぁくの中からストレスなくダビ娘へ行けるようにする。
4. 馬検索（ダビ娘）を単体でも使えるようにする。
5. PC の馬の入力欄にも「お気に入りのみ」を入れる。
6. ダビふぁくのデータにいない馬（後述の 65 頭）には ❤ を付けない。
7. 単体で使うとき、カードをタップしても何も起きない（今のダビ娘と同じ）。

### 1.2 馬の ID は機械的に対応する

ダビ娘の馬は `HorseId`（例 `3315497239`）と `Gender`（`"0"` 種牡馬 / `"1"` 繁殖牝馬）で、ダビふぁくの馬は `id`（例 `s3315497239`）で識別する。次の規則で 1 対 1 に対応する。

```
ダビふぁくの id = (Gender === "0" ? "s" : "b") + HorseId
```

ダビふぁくの 2,914 頭（2026-09-01 のデータ。週次の更新で増減し、2026-09-11 時点は 2,932 頭）はすべてこの規則でダビ娘に見つかり、衝突もない。ダビ娘にだけいる馬が 65 頭あり、うち 51 頭は同じ名前・同じ性別の馬がダビふぁく側に別 ID でいる（例: カズタカイザー、ジムフレンチ）。残る 14 頭は「-翔天-」「-覇煌-」のような新しめのバリエーションで、ダビふぁくのデータ取得がまだ拾っていない。

名前での突き合わせは使わない。ダビふぁくは `name` ＋ `subName`（`アイアンリージ` ＋ `巌瓏`）、ダビ娘は結合形（`アイアンリージ-巌瓏-`）で持っており、2,914 頭中 1,639 頭で表記が違う。年号付きの馬（`アグネスタキオン2008`）は結合の規則まで違う。

### 1.5 同一オリジンの iframe で確かめたこと

本番サイト上で、ダビふぁくのページにダビ娘を iframe で埋め込んで実測した（デスクトップ Chromium）。

- GitHub Pages は `X-Frame-Options` も CSP も返さない。埋め込みはブロックされず、親から `contentDocument` を読める。
- iframe の中から、親と同じ IndexedDB（`dabifaku_unified` の 4 ストア）が見えた。
- iframe はダビ娘自身の Service Worker（scope `/dabimas-data/dist/`）に制御されていた。**2 つの SW を統合する必要はない。**
- iframe の読み込み完了まで 49ms、検索画面が出るまで 498ms（本番の gzip 配信）。gzip なしのローカルサーバー経由では 1〜2 秒だった。iPhone での時間は測っていない。
- ダビふぁくの全データを読んだ状態で JS ヒープは 33.8MB、ダビ娘のデータも載せると 59.6MB。

本節と §1.1 の時間・容量はデスクトップ Chromium での実測である。

### 1.6 iPhone のホーム画面アプリは、インストールごとに保存領域が分かれる

統合版仕様 §1 のとおり、iOS のホーム画面アプリは同じ URL でもインストールごとに保存領域が分かれる。ダビふぁくのカテゴリ・作業枠・保存配合は IndexedDB にしかなく、書き出しと読み込みの機能もない。そのため、**ダビふぁくの URL（`/dabimas-factor/`）は動かせない。** ダビ娘は端末に何も保存していないので、ダビ娘側の URL が変わっても失うものはない。統合の向きは「ダビ娘をダビふぁくに入れる」の一択になる。

## 2. 設計方針（先に結論）

1. **ダビ娘は、既存の `/dabimas-data/dist/` を同一オリジンの iframe で埋め込む。** ビルドも配信も今のまま（ダビ娘のリポジトリで、埋め込み用の挙動をクエリで切り替える）。ダビふぁく側にビルドの仕組みは持ち込まない。
2. **埋め込みは 2 通り。** ホームから開く単体画面（`?embed=1`）と、馬選択ダイアログの「条件で探す」から開くシート（`?picker=1&sex=0|1|any`）。
3. **ダビ娘とダビふぁくは `postMessage` だけでやり取りする。** ダビ娘はダビふぁくの DB に触らない（`index.html:191` の取り決め）。ID の変換（`s`/`b` ＋ HorseId）はダビふぁく側の責務とし、ダビ娘は `HorseId` と `Gender` だけを渡す。
4. **お気に入りの正本はダビふぁくの `dabifaku_unified` に新ストア `favorites` を足して置く（version 3）。** ダビ娘に表示される ❤ は親から配られる写しにする。
5. **「お気に入りのみ」は 3 か所に置き、オン・オフは 1 つの設定を共有する。** ダビ娘の検索画面、スマホの馬選択ダイアログ、PC の入力欄。馬選択ダイアログでは 60 頭の上限を外す。
6. **旧ダビ娘は畳まずに生かしておく。** トップで開かれたときに移行案内のバナーを出すかは、Phase B の公開後に判断する（Phase C）。iframe の中身と同じアプリなので、旧 URL を消すときに要る後始末（自分の登録を解除してキャッシュを消すだけの SW や、移転ページ）は要らない。

方針 1 と 6 はプロトタイプでは検証していない（プロトタイプは `tmp/` にコピーしたビルドを使った）。設計の段階で判断した点であり、理由は §3.2 に書く。

## 3. 埋め込みの構成

### 3.1 iframe の URL と 2 つのモード

| モード | 開く場所 | iframe の URL | ダビ娘側の挙動 |
|---|---|---|---|
| 単体 | ホームの「ダビ娘」タイル | `/dabimas-data/dist/?embed=1` | カードを枠で囲み、❤ と「お気に入りのみ」を出す。カードのタップでは何も起きない |
| 馬選択 | 馬選択ダイアログの「条件で探す」 | `/dabimas-data/dist/?picker=1&sex=0` など | 単体の挙動に加えて、カードのタップで選択し、下部バーで確定する。`sex` に合わせて種牡馬・牝馬のタブを先に選んでおく |
| なし（トップ） | 旧ダビ娘のアイコン、直接の URL | `/dabimas-data/dist/` | 今のダビ娘のまま（Phase C を行う場合は移行案内のバナーを足す。§8） |

`sex` はセルの規則（§1.3 の horse-cell `lists()`）で決める。

| セル | `sex` |
|---|---|
| 繁殖牝馬側の本馬（index 16） | `1` |
| 母方の祖先（index % 16 が 3, 5, 7, 9, 11, 13, 15） | `any` |
| それ以外（種牡馬側の本馬、父方の祖先） | `0` |

iframe の URL の土台（`/dabimas-data/dist/`）は定数 1 か所にまとめ、ローカル検証のために差し替えられるようにしておく（§11.1）。

### 3.2 既存の `/dabimas-data/dist/` を使う理由

埋め込み専用のビルド（例: `/dabimas-data/embed/`）を別に作る案と比べて、既存の URL を使うほうが得るものが多い。

| 観点 | 既存の `dist/` を使う（採用） | 埋め込み専用のビルドを足す |
|---|---|---|
| ダビ娘のビルドと自動更新 | 変更なし | `update-horse-data.yml` にビルドを 1 本足す |
| リポジトリの容量 | 増えない | 14.5MB の JSON のコピーがもう 1 組でき、毎週の更新で履歴が膨らむ |
| 旧ダビ娘の利用者 | そのまま使い続けられる。案内を出すなら、トップのときの表示にバナーを足すだけ | 旧 URL を別に扱う必要がある |
| オフライン | ダビ娘の既存 SW がそのまま効く | SW をもう 1 つ持つ |

埋め込みかどうかはクエリで決まるので、同じビルドがトップでは今のダビ娘として、iframe の中では埋め込みとして動く。

### 3.3 Service Worker とオフライン

ダビふぁくの SW（scope `/dabimas-factor/`）とダビ娘の SW（scope `/dabimas-data/dist/`）は、それぞれ別に動かしたままにする。iframe がダビ娘の SW に制御されることはデスクトップで確認済み。iPhone のホーム画面アプリの中で、iframe から SW が登録されてオフラインで開けるかは**実機で未確認**であり、実装後に確かめる（§12）。

## 4. ダビ娘とダビふぁくのメッセージ仕様

やり取りはすべて `window.postMessage` で行い、受け手は `event.origin === location.origin` のときだけ処理する（他オリジンからの偽装は無視する。プロトタイプで確認済み）。知らない `type` は無視する。将来の変更に備えて、全メッセージに `v: 1` を付ける。

| 向き | type | 中身 | いつ |
|---|---|---|---|
| ダビ娘 → 親 | `dabimas:hello` | `{ v, mode: "embed" \| "picker" }` | 検索画面が表示されたとき |
| 親 → ダビ娘 | `dabimas:favorites` | `{ v, supportedKeys?, favoriteKeys, favoritesOnly }` | `hello` への返事（`supportedKeys` 付き）と、お気に入りか「お気に入りのみ」が変わるたび（全 iframe へ） |
| ダビ娘 → 親 | `dabimas:favorite-toggle` | `{ v, horseId, gender }` | ❤ が押されたとき |
| ダビ娘 → 親 | `dabimas:favorites-only` | `{ v, value: true \| false }` | ダビ娘の「お気に入りのみ」が押されたとき。親が設定を保存し、`dabimas:favorites` で全 iframe に配り直す |
| ダビ娘 → 親 | `dabimas:select` | `{ v, horseId, gender, name }` | 下部バーの「この馬を入れる」が押されたとき（馬選択のみ） |
| 親 → ダビ娘 | `dabimas:reset-pick` | `{ v }` | 別のセル用に開き直したとき、馬を入れ終わったとき |

キーの形はダビ娘側が `"<HorseId>-<Gender>"`（例 `"3315497239-0"`）、ダビふぁく側が `id`（例 `"s3315497239"`）で、変換は親だけが行う。`supportedKeys` はダビふぁくの `horsesBase` のうち `^[sb]\d+$` の id をダビ娘のキーに変換した 2,914 件で、ダビ娘はこれに含まれない馬に ❤ を出さない。親は `hello` を受けた時点で `horsesBase` がまだ読めていなければ、読めるまで待ってから返す。

`dabimas:select` を受けた親は、次の順に確かめる。

1. `findSummaryHorse({ id })` で見つからなければ、トースト「『◯◯』はダビふぁく未対応の馬です」を出して終わる（シートは閉じない）。
2. セルの `sex` に合わなければ、トースト「このセルには種牡馬しか入りません」（または繁殖牝馬）を出して終わる。
3. 通れば、シートを閉じ、`dabimas:reset-pick` を送り、馬選択ダイアログの `selectMobileHorse(summary)` を呼ぶ。以降は本番と同じ経路でセルに入る。

親の受け口（`vue/logic/musume-link.js` の `readMessage()`）は、オリジンのほかに、送り元が自分の iframe（単体画面・シート）であることと `v === 1` も確かめる。`dabimas:select` は、シートの iframe から来て、シートが開いているときだけ処理する。閉じた後に遅れて届いたものでセルが変わらないようにするため。

### 5.1 保存

`dabifaku_unified` を version 3 に上げ、`onupgradeneeded` に `favorites` ストアの分岐を 1 つ足す（既存の分岐と同じく `contains` で守る）。

favorites: keyPath "id"

`appMeta` に 2 つのキーを足す。版は上げなくてよい。

| キー | 値 | 用途 |

### 5.2 ❤ を付けられる馬

ダビふぁくのデータにいる馬（`supportedKeys`）だけに出し、未対応の 65 頭には出さない（要件 6）。51 頭は同名の対応馬がいるため、ダビ娘の画面では「同じ名前で ❤ あり・なし」の 2 枚が並ぶことがある。これには手を打たない（2026-09-11 確定）。データの取得処理をまとめれば消える（§9 の Phase 0）。

### 5.3 「お気に入りのみ」

| 場所 | 置き場所 | 動き |
|---|---|---|
| ダビ娘（単体・シートとも） | キーワード欄の右のボタン「♡ お気に入りのみ（件数）」 | 検索語なしならお気に入り全部、検索語や条件があれば掛け合わせ。お気に入りを見返し、整理する場所 |
| スマホの馬選択ダイアログ | 検索欄の上、右寄せのボタン | **件数の上限を外して全部出す** |
| PC の入力欄 | 候補一覧の先頭の行（`v-autocomplete` の `prepend-item`） | 押しても一覧は閉じない（`@mousedown.prevent`） |

オン・オフは 3 か所で 1 つの設定（`appMeta.favoritesOnly`）を共有する（2026-09-11 確定）。どこかでオンにすると、ほかの 2 か所もオンになる。プロトタイプではダビ娘の検索画面のボタンだけ独立していたので、本実装ではダビ娘も親から `favoritesOnly` を受け取り、切り替えも親に頼む形にする（§4 のメッセージに `favoritesOnly` を足す）。

「お気に入りのみ」で絞るのは、id が `^[sb]\d+$` の馬（ダビふぁくのデータの馬）だけにする。それ以外の自家製馬（`ch_…`）、編集種牡馬（`es_…`）、id のない馬は常に出す。

## 6. 画面仕様（プロトタイプで確定）

### 6.1 ホーム画面は「馬を探す」と「カテゴリ」の 2 区画に分ける

```
┌ ダビふぁく              ＋  編集  ⚙ ┐   ← アプリバーは今のまま（🔍 は置かない）
  馬を探す                               ← 小見出し
 ┌───────────────────────────────┐
 │ 🔍  ダビ娘                      ›  │   ← タイル
 │     馬を探す・お気に入りを付ける      │
 └───────────────────────────────┘
  カテゴリ                               ← 小見出し
 ┌──────────────┐ ┌──────────────┐
 │  (既存のカテゴリカード)  │ │                │
```

- 小見出しは 13px・太字・ブランド色 `#5b4b8a`、余白は上 16px・左右 12px・下 6px。
- タイルは `v-card outlined`、角丸 12px、高さ 64px 以上。文字はカテゴリカードに寄せる（「ダビ娘」15px/600、説明 12px の灰色 `#757575`）。
- タイルとカテゴリの格子の左右を 12px にそろえる（格子の `v-container` の padding を `4px 12px 12px` に）。カード同士の隙間は既存の 8px のまま。
- カテゴリが 1 つもないときも、タイルは「まだカテゴリがありません」の上に同じそろい方で出す。
- タイルは編集モードでも削除・並べ替えの対象にしない。
- アプリバーに 🔍 は置かない。アプリバーは一覧と一緒にスクロールで流れるので、🔍 はすぐ下のタイルと同時に見えて同時に消え、役割が重なる。
- スマホ表示では、ホーム自身をスクロールの器にする（設定画面と同じ方法）。`.exp-mobile-layout` が画面の高さで `overflow: hidden` のため、Phase B の前は、画面からはみ出したカテゴリカードにスクロールでも届かなかった。小見出しとタイルでカードが約 140px 下がるので、合わせて直した。

もとの設計（タイルを格子の外に置く）では、タイルの左右が画面端から 12px、カードが 2px、タイルとカードの間が 2px、カード同士が 8px とばらばらで、タイルが後から貼ったように浮いて見えた。

### 6.2 ダビ娘の単体画面

- `currentScreen = "musume"` の全画面。シートにはしない（戻る先がない目的地なので）。
- ヘッダは「‹ ホーム」（左）と「ダビ娘」。高さ 48px。「‹ ホーム」は `workspaceSync.goHome()`。
- 残りの高さいっぱいに iframe（`?embed=1`）。一度作った iframe は画面を離れても消さず `v-show` で隠す（戻ったときに読み直さない）。

### 6.3 スマホの馬選択ダイアログ

ヘッダの操作ボタンの先頭に「条件で探す」（青いボタン）を足し、本文の検索欄の上に「お気に入りのみ」を足す。

「お気に入りのみ」は `filteredMobileLists` の繰り返しの中で、上限の判定より前にかける。オンのときは上限を外す。

### 6.4 「条件で探す」のシート

- 画面の 9 割の高さのボトムシート（`v-bottom-sheet`）。上に掴み手、ヘッダは「‹ 戻る」（左）と「ダビ娘で探す ＜セル名＞」（例: 種牡馬検索 ⑩）。セル名は馬選択ダイアログの副題と同じ表記にする。プロトタイプの「種牡馬側・祖先1」は `index % 16` の番号で、画面の丸数字と一致しなかった（index 3 は ⑩）。
- **馬選択ダイアログは閉じずにシートの下に残す。**「‹ 戻る」とシートの外側のタップは、シートを下げるだけで、馬選択ダイアログが入力途中のまま出てくる。開き直す方式にしないのは、`openMobileEditor()` の `focus()` で戻るたびにキーボードが出るため。
- iframe は一度作ったら保持し、同じ `sex` なら次に開いたときも読み直さない（検索語と結果も残る）。`sex` が変わるときは URL が変わるので読み直しになる。
- 同じ iframe を別のセル用に開くときは `dabimas:reset-pick` を送り、前のセル向けに選んでいた馬を消す。同じセルで開き直したときは消さない。

### 6.5 ダビ娘のカード（埋め込み時だけ）

**枠と余白。** カードに白背景・2px の枠（`#cfd8e3`）・角丸 12px・内側の余白 8px を付ける。カード同士の空きは、グリッドの隙間ではなく**仮想スクロールの行の下の余白（14px）**で取る。行の実測高さに含まれるので、スクロール位置の計算がずれない。これで 1 枚目の上の空きは元のダビ娘と同じ 16px、カード同士は 20px になる。

グリッドの隙間を広げる方式は採らない。先頭の高さ 0 のスペーサーとの間にも隙間が入って 1 枚目の上が空きすぎ（プロトタイプでは 46px になった）、スクロール中に表示範囲が入れ替わるたびに位置もずれる。

**❤。** カード右上の角に掛かる白い丸ボタン。

- 見た目の丸は 32px（白、枠 1px `#e5e7eb`、影あり）、押せる範囲は 44px。丸の下端をカード上端から +14px に置く（配合理論の見出しは +16px なので重ならない）。前のカードとは 2px 空く。
- アイコンは SVG（Material Design Icons の favorite と同じ形、Apache License 2.0）。オフは灰色の線（`#9aa4b2`、太さ 2）、オンはピンクの塗り（`#e0245e`）。文字の「♥」は端末のフォントで形が変わるので使わない。
- 押したときのアニメーション。付けると、ハートが弾む（0.45 秒で 1 → 1.4 → 0.9 → 1 倍）のと同時に、ピンクの輪が広がって消える（0.5 秒で 0.7 → 1.7 倍）。外すと、小さく縮む（0.25 秒で 1 → 0.75 → 1 倍）。`prefers-reduced-motion: reduce` なら動かさない。
- アニメーション中の印は、`animationend` ではなく 600ms のタイマーで外す。視差効果を減らす設定ではアニメーション自体が走らず、`animationend` が来ないため。
- ❤ はカードの外にはみ出すので、カードの `content-visibility` を `visible` にする（仮想スクロールで描く枚数は元々少ない）。
- ❤ を押しても、カードを選んだ扱いにしない（`stopPropagation`）。

**選択（馬選択のときだけ）。** カード本体のタップで選び、同じカードをもう一度タップすると外れ、別のカードをタップすると選択が移る。非凡・天性の部分（`role="button"`）とボタンのタップは選択にしない。選ばれたカードは枠を青（`#1e6bd6`）にし、左上の縁に「✓ 選択中」のタグを掛ける。画面下に「＜馬名＞ ［やめる］［この馬を入れる］」のバーを出す（z-index はダビ娘のポップアップ 70 より下の 60）。

選び方は、名前入りボタン・見出し帯・タップで選択の 3 案を比べてタップで選択に決めた。最初に置いた名前なしの「この馬にする」ボタンは、枠のないカードの間に浮いて、どの馬のボタンか分からなかった。

### 6.6 PC の入力欄

`v-autocomplete` の候補一覧の先頭に「♡ お気に入りのみ（件数）」の行を置き、下に区切り線を引く。オンのときは `:items` を computed で絞った配列にする（オフのときは `lists` をそのまま渡し、毎回新しい配列を作らない）。

オンのときも、そのセルで選択中の馬（`getHorseKey` が一致する候補）は残す。`v-autocomplete` は `items` の中に値と一致するものがないと入力欄に何も出さないので、残さないと、お気に入りでない馬の入ったセルが空に見える。

### 6.7 起動時の画面復元

`boot()` の着地画面の決め方に `appMeta.lastScreen` を足す。`lastScreen === "musume"` ならダビ娘の単体画面に着地する。ダビ娘だけ使う人は、アプリを開くとすぐダビ娘が出る。このときもカテゴリの読み込み（`lastOpenedCategoryId`）は今までどおり行い、画面だけを差し替える。ダビ娘からホームへ戻ってカテゴリを開いたときの状態を、今の起動と同じにするため。`currentScreen` が変わるたびに `lastScreen` を保存する（`musume-host` が監視して `workspaceSync.rememberScreen()` を呼ぶ）。

`mounted()` はどの画面でも血統データの読込を始めるので、ダビ娘に着地してもダビふぁくのデータ（summary と pedigreeNodes で転送 0.4MB、裏で detail 10.7MB）は読まれる。summary は「お気に入りのみ」と `supportedKeys` に要るので残す。detail の裏読みを配合画面を開くまで遅らせるかは、任意の最適化とする（§10）。

## 8. 既存のホーム画面アプリの利用者

**ダビふぁくのアイコン**は URL が変わらないので、そのまま動き、保存データも残る。何もしなくてよい。

**ダビ娘のアイコン**も、同じ URL でそのまま動き続ける。案内を出す場合（Phase C。2026-09-11 時点で着手は保留）は、トップで開かれた（`window.top === window` で、`embed` / `picker` のクエリがない）ときだけ、画面上部に閉じられるバナーを出す。

> ダビ娘はダビふぁくに入りました。お気に入りや配合との連携はダビふぁくで使えます。［ダビふぁくを開く］

「ダビふぁくを開く」は `/dabimas-factor/` へのリンクにする。iPhone のホーム画面アプリでは、アプリの範囲外への移動は Safari で開くので、利用者はそこでダビふぁくをホーム画面に追加する。自動で飛ばす（リダイレクトする）と、アプリの外へ放り出されるだけになるのでしない。

旧ダビ娘はすぐには止めず、案内バナーを出して移行の様子を見る（2026-09-11 確定）。完全に止める（トップで開いたら案内だけにする）ことになった場合も、iframe の中身は同じアプリなので、トップのときの表示を変えるだけで済む。

アプリ名（`manifest.json` の `name` / `short_name`）は、当面「ダビふぁく」のまま変えない（§10.2）。

## 11. 実装時の注意（検証で分かったこと）

### 11.1 ローカルでの検証

iframe は同一オリジンでないと動かない。`start-lan.bat` はこのリポジトリのルートを配信するので、ダビ娘のビルド（`dabimas-data` の `dist/`）をこのリポジトリの `dabimas-data/dist/` にコピーすれば、本番と同じ URL で動く（`dabimas-data/` は `.gitignore` に足す）。ダビ娘のビルドは絶対パス（`/dabimas-data/dist/...`）で出力されるので、置き場所を変えるとそのままでは動かない。

LAN の http では Service Worker が使えない（安全でない接続のため）。PC の `localhost` では使えるので、PC で確かめるときは古いキャッシュに注意する。`launch.json` の `static` 設定（`python -m http.server`）はキャッシュを制御するヘッダを付けないので、ファイルを差し替えてもブラウザが古い JS を使い続けることがある。`start-lan.bat` の `scripts/lan_server.py` は `no-store` を付けるので起きない。

リポジトリのルートを配信すると、ダビふぁくの SW の scope が `/` になり、ダビ娘の iframe の読み込みもこの SW を通る。この SW はナビゲーションを app shell のキー（`index.html`）で保存するので、そのままではダビふぁくの `index.html` のキャッシュがダビ娘の HTML で上書きされる。そのため、`/dabimas-data/` で始まるリクエストには手を出さないようにした（本番では scope の外なので何も変わらない）。

自動の検証は 2 本ある。`node scripts/verify-musume-logic.cjs` と、ヘッドレス Chrome で動かす `scripts/verify-musume-ui.html` である。後者は `scripts/lan_server.py` で配信し、`scripts/codex-powershell.ps1 dump-dom` で結果を読む（手順は作業指示書の「検証コマンド」）。

### 11.2 そのほか

- ダビ娘のカードの ❤ を、馬名を包む `<label>` の中に置いてはいけない。`<label>` の中のボタンは、馬名のタップでも押されてしまう（プロトタイプの ❤ 案 A で踏んだ）。
- `mobile-horse-picker` の `runAfterMobileDialogClose()` は `requestAnimationFrame` を待つ。ダイアログがすでに閉じていても、呼べばセルへの確定は行われる。
- ダビ娘の結果一覧は仮想スクロールなので、画面外のカードは DOM にない。自動テストでカードを数えるときは注意する。カードに `content-visibility: auto` が付いている間は、画面外のカードの `innerText` が空になる（`textContent` を使う）。
- ダビ娘の起動を待つときは、iframe の `load` ではなく、検索欄が出て「起動中」の表示が消えたことを見る（`load` は JSON の読込前に来る）。

## 12. 受け入れ基準

実装後、次をすべて満たすこと。1〜12 はプロトタイプで確認済みの挙動で、本実装でも同じになること。挙動は主にデスクトップ Chromium（375〜390px 幅）で確かめ、見た目と操作感は iPhone で見てもらって決めた。ただし 8 の「61 頭以上」は、上限を外すコードを確かめただけで、実際に 61 頭を並べてはいない。13〜16 はまだ確かめていない（16 はプロトタイプではダビ娘の画面だけ独立していた）。

**2026-09-11 の Phase B 検収時点:** 1〜12 と 16 は、§11.1 の自動の検証で確かめた。8 の「61 頭以上」も、Node の検証で 70 頭・90 頭を並べて確かめた。15 は Phase A の検収で確認済み。残りは 13 と 14 で、どちらも iPhone の実機での確認が要る（14 は公開後）。

1. ホームに「馬を探す」「カテゴリ」の小見出しがあり、ダビ娘のタイルとカテゴリカードの左右が画面端から 12px でそろう。アプリバーは「＋・編集・⚙」のまま。
2. カテゴリが 0 件でも、タイルが「まだカテゴリがありません」の上に出る。編集モードでタイルに削除・並べ替えのボタンが出ない。
3. タイルでダビ娘の単体画面が全画面で開く。「‹ ホーム」で戻る。
4. ダビ娘の単体画面を開いたままアプリを閉じて開き直すと、ダビ娘に着地する。
5. ダビ娘のカードに ❤ が出る。ダビふぁく未対応の馬（例: カズタカイザー `s0314537268`）には出ない。同名の対応馬（`s1074824357`）には出る。
6. ❤ を押すと、ダビふぁくの `favorites` に `s`/`b` 付きの id で保存され、開いている全部のダビ娘（単体・シート）で点灯する。アプリを開き直しても残る。
7. ダビ娘の「お気に入りのみ」で、検索語なしならお気に入りだけが並ぶ。
8. 32 個すべてのセルの馬選択ダイアログに「条件で探す」と「お気に入りのみ」がある。「お気に入りのみ」をオンにすると、61 頭以上のお気に入りも全部並ぶ。
9. 「条件で探す」で、セルに合った `sex` のタブでシートが開く。カードのタップ → 下部バー → 「この馬を入れる」で、セルに馬が入り、祖先 15 頭も埋まる。シートと馬選択ダイアログは両方閉じる。
10. 性別の合わない馬とダビふぁく未対応の馬は入らず、トーストが出る。他オリジンからのメッセージは無視される。
11. シートの「‹ 戻る」と外側のタップで、馬選択ダイアログが入力途中のまま出てくる。同じセルでもう一度開くと検索結果と選択中が残り、別のセルで開くと選択中が消える。
12. PC の入力欄の候補一覧の先頭に「お気に入りのみ」の行があり、押しても一覧が閉じない。
13. ❤ のアニメーションが付く。iPhone の「視差効果を減らす」をオンにすると動かず、表示が崩れない。
14. iPhone のホーム画面アプリで、一度開いたダビ娘が機内モードでも開ける（§10 の未確認事項）。
15. ダビ娘をクエリなしで開くと、今のダビ娘と同じ見た目である（Phase A）。Phase C を行った場合は、移行案内のバナーだけが足されている。
16. 3 か所（ダビ娘の検索画面、スマホの馬選択ダイアログ、PC の入力欄）のどこかで「お気に入りのみ」をオンにすると、ほかの 2 か所もオンになり、アプリを開き直しても保たれる。

## 付録 A. プロトタイプで決めたこと

`tmp/prototype-search-modal/` のプロトタイプ（本番の `index.html` のコピーに検証用のスクリプトを足したもの。本番ファイルは変更していない）を、iPhone で 7 ラウンド触って決めた。`tmp/` は git の管理外で、検証が済んだら消すので、残す価値のあるものは本書と下記の 2 ファイルに移してある。

| ラウンド | 論点 | 比べた案 | 決定と理由 |
|---|---|---|---|
| 1 | 馬選択から開くときの器 | 入れ子ダイアログ / 全画面 / ボトムシート / 画面切替 | ボトムシート |
| 2 | どの馬を選ぶのかの示し方 | 名前入りボタン / 見出し帯 / タップで選択＋確定バー | タップで選択。名前なしのボタンは、枠のないカードの間でどの馬のものか分からなかった |
| 3 | シートの閉じ方 | — | 馬選択ダイアログへ 1 段だけ戻る。配合画面まで戻ってしまうのが不満だった |
| 4 | ❤ と単体画面 | — | §5・§6.2 の形 |
| 5 | ❤ の位置 | 名前の行 / カード下端のボタン / 角の丸ボタン | 角の丸ボタン。最初の「カード上端に帯を空けて右端に ❤」は、空の帯に ❤ が浮いてださかった |
| 6 | 角の丸ボタンの仕上げ | — | SVG のアイコン、アニメーション、1 枚目の上の空きの修正、「至高」の見出しとの重なりの解消 |
| 7 | ホームのダビ娘の入口 | 横長タイル / カードの 1 枚 / 見出しで区切る | 見出しで区切る。アプリバーの 🔍 は外す |

プロトタイプの親側の実装は `docs/dabimusume-integration/host-prototype.js`、ダビ娘側の差分は `docs/dabimusume-integration/musume-embed.diff` に残した。どちらも検証用に書いたもので、テンプレートを文字列で差し替えるなど本実装にそのまま使える書き方ではない。挙動を確かめる参考として使う。
